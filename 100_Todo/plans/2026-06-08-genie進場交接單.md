## 一、任務目標

修好 about-me 頁最上方「**從重啟自我，到設計產品體驗**」字卡（黑色 macOS 故事視窗 `.about-window`）的 **Genie 進場動畫卡頓**，並讓落定更有彈性。

- 目標元素：`app/about-me/page.tsx` 約 line 364 的 hero section，標題 `id="about-title"`。
- Hming 在意：① 進場要**滑順不卡**；② 落定要**彈一點**（已加 `back.out` overshoot）；③ 陰影不要硬跳出。

---

## 二、卡頓根因（已確認）

原本用 `clip-path` 多邊形逐幀變形做漏斗。問題：
1. **`clip-path` 動畫無法 GPU 合成** → 每幀主執行緒重繪整張卡（含頭像 + 文字），Retina 放大成本 ×4。← 主因
2. 外層 `filter: drop-shadow(40px blur)` 跟著變形輪廓逐幀重算模糊。← 次因

**結論：要真正不卡，只能離開 clip-path（用 canvas 或純 transform）。**

### 路線 B（目前 live，Hming 指定參考 ui-layouts/mac-genie）

**參考原始碼**：`https://www.ui-layouts.com/components/mac-genie`

## 四、路線 B 的硬傷（實測數據）

把原版確實隱藏後乾淨實測（1440×900，dev 模式）：

```
0 ──────────── ~1.2s          ~1.9s
│   全空白(無卡片)  │ genie+彈跳 │ 落定
```

- **dev 模式首屏 hero 有約 1.2 秒全空白**：`html-to-image` 拍一張 1210×415 卡片約 900ms–1s，期間卡片區是空的。
- 對「頁面最上方、一載入就要顯示」的 hero 是硬傷（沒有 idle 緩衝可藏成本）。
- 其他副作用：① 必須 `skipFonts:true`（不然 next/font 嵌字型會**卡死**），動畫期間文字在 Retina 上略糊（結束換回真卡片就清晰）；② 多一個依賴。

## 五、★ 待 Hming 決策（下一步從這裡開始）

**選項 1：先測 production 真實空白秒數**（Claude 的傾向）
- dev 1.2s 有 Turbopack/HMR 拖累；production build 可能快到 ~0.4–0.6s。
- 做法：`npm run build` 已過 → `npm run start -p 4000`（dev server 在 3000 不要關），用瀏覽器實測「載入 → genie 開始」的空白秒數。
- 若 < ~0.5s → 留 canvas genie（路線 B），收尾即可。

**選項 2：改回方案 1（純 transform）**
- 在 `AnimatedContent.tsx` genie 分支或新元件，用 `transform: scale/translate` 做「從底部中央升起 + 展開」，`transform-origin: bottom center`。
- 優點：GPU 合成、**零空白、零依賴、永遠清晰**，可加同款 `back.out` 彈跳。
- 代價：沒有逐列漏斗曲線（變成整張一起縮放彈起，不是 macOS 招牌的漏斗收口）。
- 收尾要做：移除 `html-to-image` 依賴、刪 `GenieReveal.tsx`、page.tsx 改回 `AnimatedContent`（或新 transform 元件）。

> 兩個方案的選項框 Claude 已跟 Hming 討論過，Hming 傾向「先看 production 數字再定」。Codex 接手先問 Hming 要走哪個。
